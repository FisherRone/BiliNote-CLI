# BiliNote-CLI 输出改版实施计划

## 可行性结论
三项设计全部可行。search 增强所需的发布时间（pubdate）、简介（description）、标签（tag）均在 B 站搜索 API 单次响应中，只需在 `searcher.py` 加三行解析，零额外请求、无风控风险。极简输出的"标题"可取自 `result.audio_meta.title`。批量输出的数据（任务序号、标题、并发数、模型名）全部现成。

## 改动文件

### Part 1：极简模式（单视频，`--quiet`）
- `src/app/cli/__init__.py`：process 子命令新增 `--quiet` 参数。
- `src/app/cli/process_cmd.py` 单任务分支：
  - quiet 只在直接给 URL 的单视频处理时生效；与 `--json` 同用时直接忽略（两者是独立模式，不交互、不警告）。
  - quiet 时跳过"开始生成笔记..."头部块、分隔线、笔记预览、结尾快捷指令提示（`_show_shortcut_process_prompt`）。
  - 成功时只打印 4 行：
    ```
    ✓ 笔记生成成功！
    标题: {result.audio_meta.title}
    原链接: {url}
    保存到: {output_file}
    ```
  - 失败输出不变（✗ + 错误信息，错误必须可见）。

### Part 2：批量输出调整
- `src/app/cli/process_cmd.py` 多任务入口：删除与批量头部重复的 `批量处理 N 个视频...` 行。
- `src/app/services/batch_processor.py` `process()`：
  - 新增 `model_name` 参数，头部按设计打印 `开始批量处理: N 个任务 (AI 并发: 3)` + `使用模型: {model}`；删除头部的"输出目录"行（尾部已有）。
  - 删除过程噪音：`[i/n] 准备:`、`----`、`[i/n] 提交 AI:`、`等待剩余 N 个 AI 任务完成...`（背压逻辑本身保留，只去打印）。
  - 建立 task_id → (序号, 标题) 映射，任务行统一为：
    - `  ✓ 任务{idx} 完成: {标题} - {task_id}`
    - `  ✗ 任务{idx} 失败: {task_id} - {错误文本}`（准备失败、AI 失败、异常统一此格式，序号用原始 1-based 序号）
  - 尾部统计块保持现状（已与设计一致）。
- 错误传递修正：`process_cmd.py` 的 `prepare_func`/`ai_func` 不再自行 print 并吞掉异常——异常交给 `_ai_worker` 捕获并返回错误文本，这样失败行能带上真实错误而非固定的"准备阶段失败/AI 处理返回空结果"。

### Part 3：search 输出增强
- `src/app/services/searcher.py`：
  - bilibili 解析新增：`pubdate`（unix 时间戳 int）、`description`（str）、`tags`（逗号串拆分为 list）。
  - youtube 侧对应新增（flat 模式下常缺失，全部 None 容忍）：`timestamp` → pubdate、description、tags。
  - 更新 `search()` docstring 字段清单。
- `src/app/cli/search_cmd.py` 结果行改为设计格式：
  ```
  1. {author} - {标题}
  发布时间：{YYYY-MM-DD}  播放量：3.4w  点赞量：120  收藏量：45  时长：7min
  简介：{单行化、截断 500 字符加 …}
  标签：{a、b、c}
  ```
  - 各字段缺失则跳过对应片段（YouTube flat 模式常见）；author 缺失退化为仅标题；简介/标签整行为空则整行不打印。
  - 数字单位沿用现有 `format_count`（k/w）、时长沿用 `format_duration`（7min）；发布时间用 `datetime.fromtimestamp().strftime('%Y-%m-%d')`。
- JSON 兼容性：结果 JSON 通过 `{"index": i+1, **item}` 自动带上新字段；`process --json` 只依赖 `link`/`index`，完全向后兼容。JSON 中保留完整简介，不做截断。

## 顺带说明（不在本次改动范围）
- B 站搜索当前排序是 `OrderVideo.SCORES`（最多评论）而非综合排序，属既有行为，本次不动。
- 笔记默认目录实际为 `~/.bilinote/data/output/notes`（config 可覆盖），设计示例中的路径仅为示意，代码打印真实路径。
