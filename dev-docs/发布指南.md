# BiliNote-CLI 发布指南（更新版本 + 上传 PyPI）

> 更新于 2026-10-02。本项目的发布没有走 GitHub Actions，全部在本地完成：
> 核心是根目录的 **`publish.command`** 脚本 + `uv build` / `uv publish`。

## 0. 前置认知

| 事项 | 说明 |
| --- | --- |
| 发布脚本 | `publish.command`（仓库根目录，已被 `.gitignore` 忽略） |
| PyPI 凭据 | Token 硬编码在 `publish.command` 第 102 行（`UV_PUBLISH_TOKEN=...`），**不要把该文件提交或分享** |
| 构建后端 | hatchling，由 uv 驱动（`uv build` / `uv publish`） |
| git tag | 目前没有打 tag 的习惯，发版不涉及 tag |

## 1. 标准流程（用 publish.command，推荐）

### 第 1 步：编辑脚本顶部两处

打开 `publish.command`，改最上面的用户配置区：

```bash
VERSION="0.1.5"          # ← 改成新版本号
CHANGELOG="### Added
- 本次版本的更新内容（markdown 文案，会原样写进 CHANGELOG.md）
"
```

### 第 2 步：发布前检查

```bash
# 测试（venv 里全局 bilinote 入口已过期，直接用模块方式跑 pytest）
.venv/bin/python -m pytest -m "not integration"

# lint（CI 会跑同样规则）
.venv/bin/ruff check src tests

# 本地冒烟（editable 方式验证 CLI 能起）
PYTHONPATH=src .venv/bin/python -m app.cli --help

# 若本次改过 config.yaml.example，验证模板 format() 不炸（详见《config.yaml升级与变更注意事项.md》）
PYTHONPATH=src .venv/bin/python -c "from app.config_manager import _load_default_config; _load_default_config()"
```

### 第 3 步：运行脚本

```bash
bash publish.command
```

脚本会自动完成（失败会自动回滚 pyproject.toml 和 CHANGELOG.md）：

1. **幂等检查**：CHANGELOG.md 里已有该版本条目则直接退出（可放心重复执行）；
2. `sed` 把 `pyproject.toml` 的 `version` 更新为 `$VERSION`；
3. `awk` 在 CHANGELOG.md 的第一个版本条目前插入 `## [x.y.z] - 今日日期` + 你写的 CHANGELOG 文案；
4. 删除旧 `dist/`，执行 `uv build` 生成 wheel + sdist；
5. `uv publish` 上传到 PyPI。

成功输出 `✅ 发布完成`，文件修改保留；失败输出 `❌ 发生错误，正在回滚文件...`。

## 2. 一个脚本不会替你处理的坑：`## [Unreleased]` 段

CHANGELOG.md 顶部维护着一个 `## [Unreleased]` 段（积累未发布的变更）。脚本的插入逻辑只认 `## [数字版本号]`，会把新条目插在 **Unreleased 段之后**，而不会把 Unreleased 内容合并进新版本。

发布前二选一：

- **方式 A**：手动把 `## [Unreleased]` 改名为 `## [0.1.5] - 2026-XX-XX`，脚本里 `CHANGELOG` 变量留一段简短摘要即可；
- **方式 B**：把 Unreleased 里的要点抄进脚本 `CHANGELOG` 变量，发布后手动清空 Unreleased 段。

不处理的话，Unreleased 的内容会一直挂在"未发布"名下，PyPI 上那个版本对应不到这些变更。

## 3. 手动发布（脚本之外，备用）

适合只想发一版、不想动脚本的场合：

```bash
# 1. 手动改 pyproject.toml 的 version 和 CHANGELOG.md
# 2. 构建并上传
rm -rf dist/
uv build
UV_PUBLISH_TOKEN=$(grep -o 'pypi-[^"]*' publish.command | head -1) uv publish
```

想先试水可发到 TestPyPI：

```bash
uv publish --publish-url https://test.pypi.org/legacy/
```

## 4. 发布后验证

```bash
# 全新环境拉一遍（别用本地 dist 装，验证的是 PyPI 上的包）
uvx bilinote-cli@0.1.5 --help
# 或
pipx install bilinote-cli==0.1.5

# Windows/Mac 快捷方式依赖 wheel 里 force-include 的 BiliNote.shortcut，
# 新环境跑一次确认它被正确打进了包
```

> **排障：构建报 `Forced include not found: .../BiliNote.shortcut`** —— 是仓库根目录的 `BiliNote.shortcut` 被删了（2026-10 曾两次被功能提交顺带删掉）。恢复：`git checkout origin/main -- BiliNote.shortcut`。仓库已内置 pre-commit 钩子拦截此类删除（`.githooks/pre-commit`）；注意 `core.hooksPath` 是本地配置，新机器克隆后需执行 `git config core.hooksPath .githooks` 启用。

也可直接看 <https://pypi.org/project/bilinote-cli/> 确认版本和描述。
