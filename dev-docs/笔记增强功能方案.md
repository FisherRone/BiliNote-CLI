## 笔记增强功能方案

### 目标

在 Bilibili 视频笔记中增加三处变化：新文件名格式、视频信息头部、热门评论尾部。

---

### 现状

当前笔记文件名是 `{BV号}.md`（如 `BV1vc411b7Wa.md`），笔记内容由 GPT 生成后仅在开头插入一行 `> 来源链接：<url>`，没有视频元信息，也没有评论区内容。

`yt_dlp.extract_info()` 返回的 `info` dict 已经包含 `uploader`、`description`、`title`、`view_count`、`like_count` 等字段，只是代码里只取了 `title`、`duration`、`thumbnail`、`id`。`bilibili-api-python` 已安装但未使用，其 `comment.get_comments()` 可以按点赞排序获取评论，每条评论含 `content.message`、`member.uname`、`member.level_info.current_level`、`like` 等字段。

---

### 方案

#### 1. 新增模块：`src/app/utils/bilibili_meta.py`

一个纯函数模块，职责单一：给定 BV 号或视频 URL，返回结构化的视频元信息和热门评论。

```python
@dataclass
class BilibiliVideoMeta:
    title: str
    uploader: str           # UP主名称
    uploader_id: str        # UP主 mid
    description: str        # 视频简介
    view_count: int
    like_count: int
    coin_count: int
    favorite_count: int
    share_count: int
    tags: list[str]

@dataclass
class BilibiliComment:
    uname: str              # 评论者昵称
    level: int              # B站等级 (0-6)
    message: str            # 评论文本
    like_count: int         # 点赞数

def fetch_bilibili_meta(video_id: str) -> BilibiliVideoMeta | None
def fetch_top_comments(video_id: str, n: int = 10) -> list[BilibiliComment]
```

**数据来源**：

- `fetch_bilibili_meta` 使用 `yt_dlp.extract_info(download=False)` 获取，复用现有 cookie 逻辑。不额外下载任何文件。
- `fetch_top_comments` 使用 `bilibili_api.comment.get_comments(oid, type_=VIDEO, order=OrderType.LIKE)` 获取，按点赞排序，取前 n 条。用 `asyncio.run()` 包裹异步调用。

**失败处理**：两个函数均返回 `None` / `[]`，不阻断主流程。评论获取失败时笔记照常生成，只是没有评论区尾部。

#### 2. 修改 `cli.py` 中 process 命令的文件名逻辑

**当前**（第 387 行）：
```python
output_file = path_manager.get_note_output_path(task_id)  # → {BV号}.md
```

**改为**：从 `result.audio_meta.raw_info` 中取 `uploader` 和 `title`，拼接为：
```
{uploader} - {title} - {BV号}.md
```

需要做文件名安全处理（替换 `/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 为 `_`，截断到合理长度）。

**影响范围**：仅影响单任务（`process` 子命令）的保存路径。批量处理（`AsyncBatchProcessor.get_output_path`）同样需要修改，方法一样。

在 `PathManager` 上新增一个方法：
```python
def get_note_output_path_by_meta(self, uploader: str, title: str, video_id: str, ext: str = ".md") -> str
```

#### 3. 修改 `ai_processor.py`，在笔记前后插入信息块

**在 `AIProcessor.process()` 中**，GPT 总结完成、后处理之后、最终保存之前，插入两段内容：

**(a) 头部 — 视频信息卡片**

在 `prepend_source_link` 之后，插入如下 Markdown 块：

```markdown
> **UP主**：{uploader}
> **标题**：{title}
> **简介**：{description 前 200 字，超出以 ... 截断}
> **数据**：{播放量} 播放 · {点赞数} 点赞 · {投币数} 投币 · {收藏数} 收藏
> **标签**：{tags 逗号分隔}

---
```

播放量/点赞等数字用人类可读格式（如 `12.3万`）。

**(b) 尾部 — 热门评论 Top 10**

```markdown

---

## 热门评论

| # | 用户 | 等级 | 评论 | 点赞 |
|---|------|------|------|-----:|
| 1 | 自-罚-两-杯 | Lv6 | 完美还原原版的难度... | 2041 |
| 2 | ... | ... | ... | ... |
```

若评论文本过长（超过 80 字），截断并加 `...`。若评论获取失败或为空，不插入此块。

#### 4. 数据流变化

```
TaskPreparer.prepare()
  └─ BilibiliDownloader.download() 返回 AudioDownloadResult
     └─ raw_info 已包含 uploader, description, view_count 等 (无需改动)

AIProcessor.process()
  ├─ gpt.summarize() → markdown            (现有逻辑不变)
  ├─ post_processor.process() → markdown    (现有逻辑不变)
  ├─ prepend_source_link()                  (现有逻辑不变)
  ├─ 【新增】prepend_video_meta(markdown, raw_info)   → 插入头部
  └─ 【新增】append_top_comments(markdown, video_id)  → 追加尾部

cli.py (保存阶段)
  ├─ 【修改】output_file 使用新文件名格式
  └─ 写入文件
```

核心原则：`raw_info`（`yt_dlp` 返回的 dict）已在 `AudioDownloadResult` 中完整保存，头部信息直接从中取，无需额外网络请求。评论区需要一次额外 API 调用。

---

### 改动文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/app/utils/bilibili_meta.py` | **新建** | `fetch_bilibili_meta` + `fetch_top_comments` + 数据类 |
| `src/app/utils/note_helper.py` | **修改** | 新增 `prepend_video_meta()` 和 `append_top_comments()` |
| `src/app/services/pipeline/ai_processor.py` | **修改** | 调用上述两个函数 |
| `src/app/utils/path_helper.py` | **修改** | 新增 `get_note_output_path_by_meta()` |
| `src/cli.py` | **修改** | 单任务和批量任务的保存文件名改为新格式 |

不需要改动 `BilibiliDownloader`、`TaskPreparer`、`batch_processor`（仅路径方法）、`prompt` 相关文件。

---

### 验证方式

1. 用一个 B 站视频 URL 执行 `bilinote process <url>`
2. 检查输出文件名是否为 `{UP主} - {标题} - {BV号}.md` 格式
3. 打开笔记，确认头部有 UP 主、标题、简介、数据、标签
4. 确认尾部有热门评论表格（10 条，按点赞排序，含昵称、等级、评论内容、点赞数）
5. 用一个评论区关闭或获取失败的视频测试，确认笔记正常生成（无评论区尾部）
6. 用非 B 站平台（YouTube）测试，确认不触发 B 站特有逻辑，笔记正常生成
